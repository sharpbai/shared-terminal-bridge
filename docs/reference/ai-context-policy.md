# 上下文策略与 Task Block 边界

目标是不要先把垃圾放进模型上下文，而不是只依赖会话后续压缩。原始事实仍在 tmux，模型只拿当前判断需要的部分。

## 数据分层

| 层 | 作用 |
| --- | --- |
| 原始 pane 历史 | tmux 保留，供人工滚屏或明确追查，不默认全量传入 |
| cursor 增量 | Core 依据上次观察基线返回新增内容，不由模型自造 offset |
| 确定性过滤 | 清理终端控制内容、去命令回显、折叠重复行 |
| 输出预算 | 限制行数/字节，明确报告裁剪，不把省略伪装为完整 |
| 任务与控制字段 | job 状态、人工中断、检查点独立返回，不被自然语言摘要吞掉 |

默认上下文预算最多 200 行、16 KiB，硬上限 1000 行、64 KiB；具体工具以运行 schema 为准。保留前部与最新输出，并返回 omitted_lines/omitted_bytes 等证据。命令或程序原文不被静默改写；标记过滤兼容字段不表示会注入目标 marker。

## 观察方式

已知会话先按名称读当前有界上下文，核对目标主机。MCP 的 terminal_read_delta 首次建立 cursor，之后使用实际返回值取得增量；cursor 属于短期进程状态，重启后需新建基线。

观察无需 lease；其他 job 运行不妨碍只读查看历史。tmux copy-mode/鼠标滚屏与 Agent 输入不同，不应为查看历史抢占写权。人和模型不应同时向同一 pane 输入普通命令；执行期间人工 Ctrl+C 仍可取消旧链。

## 模型何时继续读取

- run 已返回足够且 output_complete=true：直接判断，不机械补 context/status。
- 原任务运行中：使用 job/wait，不重发命令。
- 环境变化、人工换机或证据不足：明确补一次有限观察。
- 无变化输出：不持续搬运相同内容；等待检查点或真正状态变化。
- TUI：先找 CLI/CMD/batch，再请人工辅助，最后才有限 Agent 按键与小范围屏幕读取。

## Task Block 不是一条命令，也不是一轮模型调用

Task Block 是 Core 内部记录目标、计划范围、观察起点和预算的抽象；本身只记录，不隐式执行 Shell。早期受限 runner 是独立内部能力，不能当作当前通用模型接口。

当前 MCP/RDC 不再发布带授权计数的 terminal_task_block 工具；模型使用 run/job ID。一个用户任务可包含多个经过判断的 run，一条有效单行命令也可包含明确的多个轻量查询；模型调用轮次不由 block 或命令数量硬性绑定。

后续复杂任务编排若演进为可恢复步骤，仍须稳定身份、逐步风险边界、人工取消旧链和结果复用；不能恢复被取消步骤或自动消费新权限。见 [路线图](../roadmap.md)。
